# 项目架构边界

## 阶段 0 技术决策

| 层级 | 技术 | 职责 |
| --- | --- | --- |
| 数据与研究核心 | Python 3.10+ | 数据加载、样本定义、图像生成、特征和检索算法 |
| 后端服务 | FastAPI | 对外提供股票、日期、检索和统计 API |
| 前端应用 | React + TypeScript | 查询控制、K 线图、检索结果和收益分析 |
| 前端图表 | ECharts 或同类组件 | 收益分布、KDE 和结果可视化 |
| 数据文件 | CSV/Parquet | 第一版本地数据源，后续可替换为数据库或对象存储 |

第一阶段先实现 Python 数据与研究核心，不提前引入 Web 框架依赖。后端和前端将在对应阶段接入，保持核心算法可以被命令行、测试和 API 共同调用。

## 目录职责

```text
src/kline_retrieval/   Python 领域核心和可复用服务
tests/                 单元测试和集成测试
data/                  本地样例与开发数据，不存放大规模原始数据
docs/                  架构、数据协议和研究决策文档
```

后续扩展建议：

```text
server/                FastAPI 路由和请求响应模型
web/                   React/TypeScript 前端
```

## 模块边界

- `config.py`：只负责默认参数和环境变量配置，不执行数据加载。
- `logging_config.py`：统一日志格式和项目 logger，不在领域模块中配置全局 logging。
- `market_data.py`：只负责行情数据校验、索引和窗口查询，不负责 HTTP 或前端展示。
- K 线图模块：只接收已验证的 OHLC 数据，不读取原始文件。
- 特征和检索模块：只接收图像或向量，不直接依赖 Web 请求对象。
- API 层：负责参数校验、错误转换和响应格式，不重新实现研究算法。
- 前端：负责交互和展示，不在浏览器中执行完整历史样本扫描。

## 错误处理约定

1. 数据层使用明确的领域异常，例如 `DataValidationError`、`UnknownTradingDateError` 和窗口不足异常。
2. 命令行入口将数据异常转换为错误日志和非零退出码。
3. API 层后续将领域异常转换为稳定的 JSON 错误结构。
4. 前端只依赖错误码和用户可读消息，不解析 Python 异常文本。

## 日志约定

- 使用 `kline_retrieval` logger。
- 默认输出到 stderr。
- 日志包含时间、级别、logger 名称和消息。
- 数据文件路径、样本参数、候选数量和计算耗时属于可记录信息。
- 原始行情内容和敏感配置不直接写入日志。
