# 阶段八验证报告

验证日期：2026-10-25

## 数据口径

用户放置在仓库工作目录中的 CSMAR `TRD_Dalyr` 数据由两个目录、共10个 CSV 分片组成。用户描述中的“2028.1.1”与当前日期（2026-10-25）不一致；按文件内容核验，实际覆盖 `2018-01-02` 至 `2026-10-23`。

当前阶段采用以下检索口径：

- 月线：20根，每根20个交易日，共400个历史交易日。
- 周线：20根，每根5个交易日，共100个历史交易日。
- 日线：20根，每根1个交易日。
- 图像：64×64黑白 OHLC 图；未来20日图只用于结果展示。
- 收益标签：未来1、5、10、20个交易日，未来5日作为主分析周期。
- 距离加权：`w_i = exp(-distance_i / 0.25)`，再归一化。
- 稳定性：加权标准差、加权胜率、ESS、标准误、信号强度和近似95%区间。

`KLINE_DAILY_WINDOW=60` 可以运行60D日线敏感性配置；当前默认网站口径仍为20D，避免在阶段九建立索引前改变生产基线。

## CSMAR 导入质量

导入命令：

```bash
.venv/bin/kline-import-csmar \
  --input-dir '日个股回报率文件（1）' \
  --input-dir '日个股回报率文件（2）' \
  --database data/processed/csmar_a_share_daily.sqlite3 \
  --quality-report data/processed/csmar_a_share_daily.quality.json
```

| 股票数 | 5,428 |
| 日线记录数 | 9,074,433 |
| 最早日期 | 2018-01-02 |

可检索日期按每只股票至少具备400个历史交易日和20个未来交易日计算。数据库的 `daily_bars` 同时保留成交量、成交金额、日收益率和昨收盘字段，原始 CSV、SQLite 数据库和质量 JSON 已加入忽略规则，不提交到 GitHub。

## 200 只股票预检

按证券代码排序选取前200只股票进行覆盖预检：

- 200只代码均被发现并写入股票元数据表。
- 197只股票具备完整20D历史和20D未来窗口。
- 共321,571个可检索日期。
- 其余3只股票因历史记录不足，保留在数据库中但不作为有效检索样本。

该预检验证了全市场快照可以按股票子集加载，后续阶段九需要通过离线特征和向量索引解决全量请求时的内存和耗时问题。

使用 CSMAR SQLite 快照加载 `000002` 和 `000004` 等真实股票，以 `000002 / 2026-09-17` 为查询样本，返回5个历史匹配。未来5日统计示例：

- 距离加权平均收益：`+11.13%`
- 加权标准差：`16.69%`
- 有效样本数：`4.83`

该结果只验证数据管线、图像生成、检索、收益计算和稳定性字段能够连通，不代表收益预测有效，也不构成投资建议。

## 限制和后续

- CSMAR 日行情表本身不含证券名称和行业字段，因此“剔除 ST 和金融业”只能作为用户提供数据集的口径记录，不能从这张表独立复核。
- 当前网站直接请求时仍会按加载的股票子集扫描候选，完整5,428只股票不应在没有离线索引的情况下直接作为默认进程内数据集。
- 阶段九需要建立 ColProj 离线特征库和向量索引，并记录数据快照、图像参数、特征维度、温度参数和生成时间。
- 当前“最新日期”是数据文件中的 `2026-10-23`，不是盘中实时数据；后续每日更新仍需单独接入增量数据源或人工导入新快照。
