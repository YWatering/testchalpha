# 阶段十四验证报告

## 当前结论

阶段十四已完成结果缓存、API 缓存命中、缓存状态接口、流式断点续跑基础、ColProj/CNN 全分片三尺度 ANN 及默认权重综合 ANN。CNN 通过 PyTorch 主进程与 FAISS 常驻子进程隔离完成预计算；API 可命中两种模型的已物化结果且不加载 FAISS。全市场结果覆盖、扩大召回验收、原子发布和最终性能验收尚未完成。

## 已完成验证

- 72 项项目测试通过。
- 真实 CSMAR 重建价格库上的 ColProj 单查询缓存试点完成。
- 相同股票、日期、模型和参数再次查询时，API 返回 `materialized_colproj`，并跳过索引扫描。
- 结果缓存绑定模型、索引版本、数据快照哈希和检索参数；不复制 Base64 图像。
- ColProj 第一分片 `a-share-0001.sqlite3`：FAISS IVF-PQ 三尺度候选索引构建成功。
- CNN 第一分片 `a-share-0001.sqlite3`：FAISS IVF-PQ 三尺度候选索引构建成功。
- `kline-precompute-ann` 同时支持 ColProj 和 CNN，按股票逐段流式生成查询键并跳过已有缓存，不再一次性保存数百万查询键。
- CNN 主进程负责64×64图像与128维向量，常驻子进程只加载 FAISS；真实运行未再触发 macOS OpenMP 冲突。
- 预计算命令支持 `--all` 自动读取 ANN 清单覆盖的全部股票；仍按缓存键断点续跑，当前未直接启动数百万查询任务。
- ColProj/CNN 各28个 ANN 分片均已生成 `combined.faiss`；旧三尺度索引仍保留，任意自定义权重仍走三路候选并精确重排。
- 默认等权路径先汇总28分片近似分数，批量读取代码/日期并先执行历史日期与embargo过滤，再从合格样本中保留有界全局候选，最后读取原始向量进行三尺度精确重排。较晚日期的CNN向量读取量由每查询28,000条降至600条。
- API 可通过 `KLINE_ANN_INDEX_PATH` 和 `KLINE_CNN_ANN_INDEX_PATH` 查找双模型物化缓存；未命中时回退精确索引，API 本身不导入 FAISS。
- 真实库 `000002`、2025-01-02 单查询：综合 ANN 每分片 1,000 候选、`nprobe=64` 时读取 28,000 条候选，ANN 总耗时约4.29秒，其中 FAISS 搜索约20ms、候选读取约4.24秒、向量重排约24ms；同一查询精确索引约29.75秒。
- 新全局候选路径中，ColProj 使用候选基数1000时，`000002/2025-01-02` 与全量精确 Top-20 为20/20且顺序一致；候选基数200仅为17/20，因此两种模型不得共用同一默认值。
- CNN 使用候选基数200时，`000002`、`000333`、`300750`、`600519` 在2025-01-02的 Top-20 均与全量精确结果20/20一致且顺序一致；`000333/2020-01-02` 在时间过滤前仅15/20，修正为先过滤未来样本后恢复20/20且顺序一致。当前共5条真实对照，仍不等于全市场验收。
- 时间过滤修正版的CNN常驻 worker 连续5条查询中，首条冷启动约7.21秒，后续约0.72–0.89秒，总计约10.73秒；旧的每分片候选读取方案同批约23.33秒。
- 真实 API 命物化 CNN 修正版缓存时返回20条结果，端到端约496ms，`search_mode=materialized_ann_cnn`。
- 在此前 30 个按日期/股票顺序抽取的查询中，去除 1 个没有可用历史候选的样本后：
  - ColProj：每尺度候选数 10,000、`nprobe=64`，29 个有效查询的 Recall@20 为 100%。
  - CNN：相同配置下，29 个有效查询平均 Recall@20 为 99.31%，最低为 95%。
  - ANN 候选召回耗时约 5.8-6.5ms；该指标不包含候选读取、精确重排、收益分析和图像渲染。

## 尚未完成

- 全分片 ANN 索引已完成；目前每分片约 2 个有效查询的工程抽样不能代表充分的全市场 Recall@20。
- 尚未完成多组权重、Top-K、embargo 配置的召回率评估。
- 综合 ANN 的默认权重全量召回仍需扩大分层抽样；当前新全局候选路径只完成5条全市场精确对照。
- 尚未把 ANN 设为网站未命中时的在线搜索路径；当前 API 仅优先读取 ANN 已物化结果，未命中仍走精确索引。
- ColProj/CNN 隔离 ANN worker 均已接入结果缓存；ANN 在线未命中仍不开放，未物化查询继续回退精确索引。
- 6,862,102 个样本的双模型结果尚未全量物化。按 Top-20 二进制载荷粗估约 12.4GB，实际还要加 SQLite 索引、WAL 和参数预设。

## 下一步验收门槛

1. 扩大日期、股票规模和模型的分层随机抽样，确认综合 ANN 默认权重最低 Recall@20 不低于 95%，并记录失败样本。
2. 测量 ANN 候选读取、精确重排、收益分析和图像按需渲染后的端到端 P95。
3. 评估预计算吞吐与并行方案，明确全量物化所需时间和磁盘空间。
4. 只有全量缓存覆盖率达到 100%、版本原子发布和增量失效测试通过后，才将阶段十四标记为完成。

## 全分片 ANN 抽样补充

随后对全部 28 个 ColProj 分片和全部 28 个 CNN 分片各抽取 3 个按索引顺序分布的查询，仍使用每尺度候选 10,000、`nprobe=64`、Top-20 和 embargo=3。每个分片的最早抽样点可能没有可用历史候选，因此该点被标记为 skipped，不纳入 Recall@20 分母。

- ColProj：28/28 分片完成，平均分片 Recall@20 为 100%，最低分片 Recall@20 为 100%，无分片低于 95%。
- CNN：28/28 分片完成，平均分片 Recall@20 为 100%，最低分片 Recall@20 为 100%，无分片低于 95%。
- 这只是每分片 2 个有效查询左右的工程抽样，不能替代大规模随机分层抽样；全市场默认切换前仍需扩大样本、覆盖多组权重和验证跨分片全局重排。

## 线上接入边界

尝试在同一 FastAPI 进程内同时加载 FAISS ANN 和 PyTorch CNN 检查点时，macOS 出现两个 OpenMP runtime 冲突，查询阶段会使进程中止。没有采用不安全的 `KMP_DUPLICATE_LIB_OK=TRUE` workaround。现在 CNN 预计算由 PyTorch 主进程生成查询向量、FAISS 常驻子进程检索，两者不共享运行时；API 仍只读取物化缓存。ANN 在线未命中服务尚未开放。
