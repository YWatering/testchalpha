# 阶段十四验证报告

## 当前结论

阶段十四已完成结果缓存、API 缓存命中、缓存状态接口、可断点续跑的精确预计算基础、全分片 ANN 索引及小规模召回抽样。另已加入隔离 ColProj ANN worker；API 通过读取 ANN 清单元数据命中已物化结果，不在服务进程加载 FAISS。全市场结果预计算和性能验收尚未完成。

## 已完成验证

- 68 项项目测试通过。
- 真实 CSMAR 重建价格库上的 ColProj 单查询缓存试点完成。
- 相同股票、日期、模型和参数再次查询时，API 返回 `materialized_colproj`，并跳过索引扫描。
- 结果缓存绑定模型、索引版本、数据快照哈希和检索参数；不复制 Base64 图像。
- ColProj 第一分片 `a-share-0001.sqlite3`：FAISS IVF-PQ 三尺度候选索引构建成功。
- CNN 第一分片 `a-share-0001.sqlite3`：FAISS IVF-PQ 三尺度候选索引构建成功。
- 新增独立 `kline-precompute-ann` 命令，仅支持 ColProj，按股票/日期批量生成 ANN 检索结果并支持缓存跳过续跑；与包含 FAISS 的预计算进程分离。
- API 可通过 `KLINE_ANN_INDEX_PATH` 读取 ANN 清单身份并查找隔离 worker 生成的 ColProj 缓存。未命中时回退精确索引，API 本身不导入 FAISS。
- 真实库 `000002`、2025-01-02 单查询冒烟：成功写入缓存；查询耗时约55.2秒，其中 ANN 候选召回/精排约53.5秒、跨28分片候选计数766,219。该结果说明全量物化需评估并行吞吐，不能据单条样本外推为可快速完成。
- 在 30 个按日期/股票顺序抽取的查询中，去除 1 个没有可用历史候选的样本后：
  - ColProj：每尺度候选数 10,000、`nprobe=64`，29 个有效查询的 Recall@20 为 100%。
  - CNN：相同配置下，29 个有效查询平均 Recall@20 为 99.31%，最低为 95%。
  - ANN 候选召回耗时约 5.8-6.5ms；该指标不包含候选读取、精确重排、收益分析和图像渲染。

## 尚未完成

- 全分片 ANN 索引已完成；目前每分片约 2 个有效查询的工程抽样不能代表充分的全市场 Recall@20。
- 尚未完成多组权重、Top-K、embargo 配置的召回率评估。
- 尚未把 ANN 设为网站未命中时的在线搜索路径；当前 API 仅优先读取 ANN 已物化结果，未命中仍走精确索引。
- ColProj 隔离 ANN worker 已接入结果缓存。CNN worker 仍未实现；CNN 在线检索保持现有精确路径和单独结果缓存。
- 6,862,102 个样本的双模型结果尚未全量物化。按 Top-20 二进制载荷粗估约 12.4GB，实际还要加 SQLite 索引、WAL 和参数预设。

## 下一步验收门槛

1. 扩大日期、股票规模和模型的分层随机抽样，确认最低召回率不低于 95%，并记录失败样本。
2. 测量 ANN 候选读取、精确重排、收益分析和图像按需渲染后的端到端 P95。
3. 评估预计算吞吐与并行方案，明确全量物化所需时间和磁盘空间。
4. 只有全量缓存覆盖率达到 100%、版本原子发布和增量失效测试通过后，才将阶段十四标记为完成。

## 全分片 ANN 抽样补充

随后对全部 28 个 ColProj 分片和全部 28 个 CNN 分片各抽取 3 个按索引顺序分布的查询，仍使用每尺度候选 10,000、`nprobe=64`、Top-20 和 embargo=3。每个分片的最早抽样点可能没有可用历史候选，因此该点被标记为 skipped，不纳入 Recall@20 分母。

- ColProj：28/28 分片完成，平均分片 Recall@20 为 100%，最低分片 Recall@20 为 100%，无分片低于 95%。
- CNN：28/28 分片完成，平均分片 Recall@20 为 100%，最低分片 Recall@20 为 100%，无分片低于 95%。
- 这只是每分片 2 个有效查询左右的工程抽样，不能替代大规模随机分层抽样；全市场默认切换前仍需扩大样本、覆盖多组权重和验证跨分片全局重排。

## 线上接入边界

尝试在同一 FastAPI 进程内同时加载 FAISS ANN 和 PyTorch CNN 检查点时，macOS 出现两个 OpenMP runtime 冲突，查询阶段会使进程中止。没有采用不安全的 `KMP_DUPLICATE_LIB_OK=TRUE` workaround。ColProj 现可由独立进程离线预计算并由 API 安全读取其缓存，但 ANN 在线未命中服务仍未开放；CNN 在线仍使用精确索引和结果缓存。CNN ANN 需要单独解决运行时隔离后再建设 worker。
